## Journey and viewport coverage

The real UI journey completed synthetic signup, email verification, login, organization creation, reviewer invitation with a separate account, assessment draft/save/validate/issue, candidate consent/edit/save/resume/submit, evaluator evidence inspection, observation, review finalization, persistence reload, and logout/login. The successful run reached its final assertion; only three blocked inline-style notices in Team & Settings prevented the browser-console list from being empty. The two route-handler style attributes were removed and moved to stylesheet classes without changing CSP. Final rerun is pending.

| Journey area                | States reached through the UI                                                                                        | Viewport evidence                                                                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Public boundary and account | `/` redirect; sign-in; signup and registration receipt; email verification; local inbox; recovery/reset; form errors | All five widths for the audited account screens; CSS-delivery regression also covered invalid account-form POST states. |
| Organization                | Organization selection/bootstrap; workspace/dashboard; Team & Settings and members; reviewer invitation              | All five widths across the major organization screens and states.                                                       |
| Assessment builder          | Define assessment; save draft; validate; issue                                                                       | All five widths for builder states.                                                                                     |
| Candidate                   | Consent; editor; save/resume; submitted confirmation                                                                 | All five widths for consent, active workspace and submitted confirmation.                                               |
| Evaluator                   | Queue; evidence and files; observations; finalized review/history; returning-user login and persistence              | All five widths for the major evaluator screens; keyboard navigation was exercised in the review flow.                  |

The viewport set was desktop 1440×900, laptop 1280×800, tablet 768×1024, mobile 390×844 and small mobile 375×812. The audit collected local screenshots at each width. No screenshot was uploaded. Automated Axe ran for WCAG 2.0 A/AA and WCAG 2.1 AA at each audited state; the full journey did not print its collected result summary before the final console assertion. Final Axe and overflow counts are pending.

Keyboard checks in the journey used Space/Enter for candidate consent and activation, arrow-key tab navigation in the evaluator, and Enter to open the review packet. Journey browser contexts kept the application Content Security Policy active. The DevTools-only CSP setting applies only to Axe instrumentation. The evaluator evidence and finalized packet were visually readable on mobile in the current capture set. The long mobile candidate page remains a single-column scroll.

Public informational routes were not opened because the actual `/` navigation in this runtime redirects to sign-in and no public informational navigation is exposed there. Settings and member management are present and were visited through the organization’s “Team & Settings” link; no speculative SaaS settings features were added.
