# Hirearchy hiring experience

Start at the current GitHub main and retain the reviewed Hirearchy Software UI. Use the existing hiring routes, migrations and adapters for product behavior. Build the presentation from Hirearchy’s Common Thread brand and the reviewed Software UI.

## Interface direction

Use a compact three-stage builder, with a source catalog, candidate preview and invitation form. Rebuild the repository view and feature styles around the shared Software controls. Use a candidate directory with a dedicated filter column, a shared masthead for the candidate portal, and focused sections for the reviewer’s decision and manager’s handoff.

## Acceptance

- Independent candidate and team entry routes. A verified candidate account opens its own issued work and sees published feedback across companies. Internal notes and handoffs stay private to the authorized team.
- Candidate-centered team views with filters and sort choices for roles, stages, location, experience and skills. Team permissions distinguish owner or CTO, recruiter and evaluator.
- Templates, generated problems and saved problems in the builder. Use the platform's editor capabilities for a readable, branded repository preview. Keep saved assessment versions intact.
- Scoped organization plans and per-candidate credits, checked when issuing. Advisory AI review stays separate from the human decision. Publish feedback explicitly and carry accepted work into a named next stage.
- Cohesive warm light and plum dark surfaces. Use focused motion with a reduced-motion preference and verify the journey on narrow and wide screens.

## Local proof

Use an isolated PostgreSQL, GoTrue and mail setup to exercise candidate entry, assessment issuance, submission, human review and handoff. Exercise the NVIDIA integration with synthetic inputs. Preserve the existing read and execution behavior for legacy profiles.

The `hiring` profile runs on `127.0.0.1:3310` using its own database and local inbox. The preview contains synthetic accounts and workspaces.

- The hiring flow covered repeat issuance with zero additional credits, activation and submission, a requested and answered second opinion, acceptance with a handoff, and rejection through the rebuilt interface. Candidates received the published feedback. Team notes and second opinions stayed private.
- A second synthetic company issued an assessment to the same candidate. The credit was applied to the issuing company, and the candidate could filter assessments by either company.
- The authenticated staging presentation passed CSS delivery and the Reservation Moves recruiter, candidate and human-review journey.
